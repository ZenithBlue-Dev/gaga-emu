# 07 — Roadmap & Implementation Plan

This document is canonical for phases and status. `docs/03` is canonical for the core list, licences and renderers, `docs/04` for interpreter design and load tiers, `docs/05` for graphics, and `docs/06` for the bridge API and premium spec. Other docs do not fork this plan.

**Where the project stands:** Phase 1 is closed: the code matches the docs, and the UI redesign (1.19 to 1.21) resolved 1.13. The registry (`Sources/Bridge/GagaCoreRegistry.c`) has 38 entries: 35 real cores, the mock core, the Debug-only `vktest` layer-path test core, and a `gpsp` stub (see 1.2). Every real core is merged and builds; all are GPL or otherwise gated, so release builds leave them out through `GAGA_CORE_SET` until the legal gate (4.0) closes. Milestones 2.1 to 2.10 are built, and the core milestones in sections 7 to 11 are built. Device runs 4 to 8 (iPhone 17, iOS 27.2, 2026-11-07 and 2026-11-08) ran the unit suite, a UI walk and 10 s or 30 s benchmarks on owner-supplied games for GB, GBC, GBA, NES, FDS, SNES, N64, DS, PSP, PS1 and Mega-CD, plus the generated MD and arcade test programs; figures are in `docs/04` section 7.1 and the failures are in section 14. Cores not yet run on a device are marked "device pending" in their rows. Milestone 5.1, MoltenVK and the layer path, was proved on an iPhone 17 with the Vulkan test core. Phase 3 is built, with 3.6 (`.slangp` import), saved filter presets and rewind device-pending; RetroAchievements and iCloud Sync need owner action. AirPlay Fullscreen is built but unverified, because no second screen could be attached, so its row stays hidden. Rumble from core events, the skin editor, drag and drop on every screen, and the About rows (About Us, Share GagaEmu, Reset Tips) are built, device pending (1.14, 2.4, 7.6). Language stays hidden until a second localisation exists.

**Status terms:**

- **built:** the code exists and does its job in the shell.
- **stub:** a row, toggle or symbol exists, but nothing acts on it.
- **planned:** no code exists.
- **blocked:** cannot start until the named owner action happens.

**Tier and phase are different things.** A load tier is a core's expected CPU load (`docs/04`). A phase is delivery order. They do not map onto each other: a Tier 1 core can arrive after a Tier 2 core, and the Tier 1 PC Engine core (8.1) comes after the Tier 3 Dreamcast core (6.2). Performance figures in this plan are device measurements only where a row names the device and `docs/04` section 7.1.

**No in-house rewrites are implied.** Each milestone adopts or ports an upstream core. Writing a new interpreter, or rewriting one inside a core, would be separately scheduled work with its own milestone. None is scheduled. `docs/04` section 4.2 lists the candidates, Dreamcast first, and the condition for starting one.

## 2. Definition of Done for a Core

A core milestone closes only when all of these hold:

1. **No-JIT gate passes for this core's build.** It runs per core and on every build, not only at the end (milestone 2.7, `docs/03` section 5, `docs/04` section 8). No JIT, no RWX and no dynarec ship in any core.
2. **Licence recorded.** The core's licence is in `docs/03`. For a GPL core, the legal gate (milestone 4.0) must already be closed.
3. **Renderer path accepted.** The core uses a path in `docs/05` section 2. GLES-only and desktop-GL-only renderers are not accepted.
4. **Runs in a game session.** Video, audio, input, battery saves and save states work on a device.
5. **Benchmark recorded.** A measured result on a named device is recorded, using the method in `docs/04` section 7.2 (milestone 2.8a). Until then, any speed figure stays labelled "target (unmeasured)".
6. **Registry and catalog updated.** The core's weak stub is deleted and its `core_id` is in the registry and in `CoreCatalog`.
